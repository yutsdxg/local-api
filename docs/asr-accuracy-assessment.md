# 調査対象全体の評価：精度を最優先する場合

**実測済みの主候補は、MLX Whisper large-v3と、whisper.cpp large-v3のgreedy・履歴なし設定。対抗候補はQwen3-ASRとlarge-v3-turbo。Parakeetは今回の意味の置換を踏まえ、精度最優先の主候補から下げる。** 未実測の日本語モデルではReazonSpeech-k2-v2とKotoba-Whisper v2.0を追加比較候補に残す。

これは同じ録音に対する出力の読取比較と一次資料から判断した、採用検証の優先順位である。聴取確認済みの正解文はなく、認識精度を数値で測った順位ではない。未測定候補まで含めて最良の方式が確定したとは扱わない。

評価軸は、意味の保持、数字・固有名詞・専門語、説明や発話の欠落、長い反復の順。句読点、フィラー、文章の自然さ、処理時間、メモリ量だけで精度の上下を決めない。以前のParakeet推奨は速度・メモリ面の判断であり、精度重視の推奨としては本書で見直す。

## 実測したモデルと実行構成

前処理を固定して通常・雨・長い間のある録音を比較した。以下の「全文3本」は原録音約4分・12分・10分からの全文処理を指す。whisper.cppの版は旧1.8.2と新v1.9.4タグ、MLX系の依存・モデルrevision・入力ハッシュは[再現手順](asr-recognition.md)とローカルreportに記録している。

| 対象 | 実測範囲 | 精度に関する出力の観察 | 精度優先での判断 |
| --- | --- | --- | --- |
| **MLX Whisper large-v3** | 3抜粋・反復実行、全文3本 | 現行mediumにない理由説明を出力し、背景・作成対象・音声処理の語を保持する箇所がある。長い反復列は見当たらなかった。一方、雨の数字・製品名・動作を示す語の崩れは残る。 | **主候補。** cpp履歴なしより正確と実証したわけではない。 |
| **whisper.cpp large-v3：greedy・履歴なし** | 3抜粋・反復実行、全文3本 | 通常全文は空白・改行を除くとMLXと一致。通常設定で見つかった反復を今回の3本では生じず、主要な説明や専門語を出力。一部の対象語と増減表現はMLXとも異なる。 | **MLXと同じ主候補群。** 現行エンジンでもデコード条件の変更で検討できる。 |
| **Qwen3-ASR-1.7B / MLX** | 3抜粋・反復実行、全文3本 | 理由説明を出力し、雨の技術用語や行動表現でWhisperと異なる有益な候補語を返す。一方、作成対象や文脈を表す語を別の語へ繰り返し置換する箇所がある。 | **別系統の対抗候補。** 難所の比較に価値があるが、一律にWhisperを上回る根拠はない。 |
| **whisper.cpp large-v3-turbo** | 3抜粋、全文3本 | 理由説明、作成対象、音声処理の語を保持する箇所があり、長い反復列も見当たらなかった。一方、同じ語の別の出現箇所や、雨の動作・固有名詞には崩れがある。 | **精度面でも比較候補に残す。** 速いことだけを理由に選ばず、主候補群を上回るかは未確定。 |
| **日本語Parakeet TDT-CTC 0.6B / MLX：一括・60秒分割** | 一括は3抜粋・反復と全文3本、60秒分割は全文3本 | 説明を拾う箇所はあるが、背景・作成対象・専門語・行動を別の意味へ変える置換が複数ある。60秒分割で速度・メモリは改善したが、認識内容の一律改善は確認できない。 | **精度最優先では優先度を下げる。** 速度面の強さを精度評価へ持ち込まない。 |
| **whisper.cpp large-v3：通常のbeam 5設定** | 3抜粋、`-nt`で全文3本。timestamp有効の雨全文は途中停止 | 語句が良く見える箇所はあるが、雨全文で同一文37回連続の反復と後半の話題脱落の疑い。timestamp有効化だけでも反復が続いた。 | **今回の設定は採用見送り。** large-v3モデル自体を否定せず、履歴・探索設定を含めて判断する。 |
| **現行whisper.cpp medium / CPU** | 3抜粋、全文3本 | 長い反復列は見当たらないが、他候補が出力する説明が見当たらず、雨の専門語・製品名にも崩れがある。一部の重要語は他方式より妥当に見える。 | **比較基準・切り戻し先。** 現行が十分な精度であるとは判断していない。 |
| **mediumのMetal化・cpp更新・`-nt`解除** | 旧/新版×CPU/Metal×`-nt`有無の3抜粋。Metalの全文は未実測 | 一部の出力は変わるが、設定変更だけで認識内容が一貫して良くなった証拠はない。 | **精度改善策としての優先度は低い。** 高速化・保守更新としての価値とは区別する。 |

主候補の具体的条件は、MLXが`temperature=0`・`condition_on_previous_text=false`、cppが`-bs 1 -bo 1 -mc 0`・timestamp有効。両者は同じlarge-v3系でも、temperature fallbackなどが完全には一致しない。差を実行ライブラリだけの効果に帰属しない。

cpp履歴なしとturboについては、当初雨全文だけだった比較へ、今回通常・長い間の全文も追加した。結果は`data/asr/evaluation/accuracy-full-completion/report.json`、雨全文は`rain-diagnostics/report.json`にある。追加4件はすべて正常終了した。turboの句読点が少ない出力では文単位の反復指標だけでは不十分なため、TXTも読んで確認した。

## 資料調査までの候補

ここからは今回の録音で実測していない。実測済みの主候補より良い・悪いという順位を付けず、精度比較の価値と役割を評価する。

| 対象 | 種類 | 精度に関する根拠・限界 | 判断 |
| --- | --- | --- | --- |
| **ReazonSpeech-k2-v2** | 日本語認識モデル | 開発元の同条件比較では、JSUT・Common Voice・TEDxJPでlarge-v3より低いCERを公表。今回の屋外録音へ一般化はできない。モデル単体の長さ制約があるため、長尺は分割が必要。[開発元評価](https://research.reazon.jp/blog/2024-08-01-ReazonSpeech.html)、[モデル仕様](https://huggingface.co/reazon-research/reazonspeech-k2-v2) | **未実測のローカルモデルで追加比較を優先。** 小型・CPU向けという理由で精度候補から外さない。 |
| **Kotoba-Whisper v2.0** | 日本語向けWhisper蒸留モデル | 公式評価では放送音声由来のデータでlarge-v3より良い一方、Common Voice・JSUTではlarge-v3が良い。日本語特化だけで常勝とは言えない。[公式評価・cpp重みへの案内](https://huggingface.co/kotoba-tech/kotoba-whisper-v2.0) | **追加比較を優先。** 録音との相性を確認する価値がある。 |
| **WhisperKit / Argmax OSS** | Whisper実行ライブラリ・ローカルサーバー | Core ML版Whisperを実行する経路。エンジン名だけでは精度向上を保証しない。モデル変換・量子化・分割・デコード設定まで固定した比較が必要。[公式](https://github.com/argmaxinc/argmax-oss-swift) | **Whisper採用時の実行経路候補。** 別の認識モデルとして順位を付けない。 |
| **faster-whisper / CTranslate2** | Whisper実行ライブラリ | beam search・文脈・VAD等を比較できる。M1のMetal GPUは配布CTranslate2の対象外だが、精度優先ならCPU実行の遅さだけで棄却しない。[公式](https://github.com/SYSTRAN/faster-whisper)、[対応環境](https://opennmt.net/CTranslate2/hardware_support.html) | **同じWhisperのデコード差を確かめる候補。** ライブラリ変更自体の精度優位は未確認。 |
| **MacWhisper / `mw` CLI** | アプリケーション | 単一の独自ASRモデルではなく、選んだエンジン・モデル・設定で認識結果が変わる。CLIはアプリとローカルsocketで通信する。[公式CLI](https://docs.macwhisper.com/article/57-macwhisper-command-line-tool) | **確認・操作用のアプリ候補。** 精度評価では中のモデルを特定する必要がある。 |
| **Google Chirp 3** | 外部ASR API | 日本語対応と語彙適応機能があり、別系統の比較に価値がある。公式の改善説明は今回のローカル候補に勝つ証拠ではない。[公式仕様](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3) | **外部送信を許容する場合の比較候補。** 今回未送信・未測定なので精度順位は未確定。 |
| **ElevenLabs Scribe v2** | 外部ASR API | 日本語対応、keyterm promptingなどがある。公開の日本語WERを今回のCERや他社条件と横並びにできない。[公式仕様](https://elevenlabs.io/docs/overview/capabilities/speech-to-text) | **外部送信を許容する場合の比較候補。** 今回の音声での精度は不明。 |

## この評価からの推奨

1. **すでに実測できた構成から選ぶなら、large-v3の履歴なし認識を中心にする。** MLXとcppを主候補に残す。MLXだけが正確という結論ではなく、両者の差が小さい箇所と意味が変わる箇所がある。
2. **異なる認識方式の対抗にはQwen、Whisper系の対抗にはturboを残す。** 局所的な得意・不得意があるため、都合のよい例だけで順位を固定しない。
3. **調査対象全体から精度の最良候補を探すなら、ReazonSpeechとKotobaの実測がまだ残る。** これらを試さず、実測済みの候補だけで「最良」とは結論しない。
4. **Parakeetを速度・メモリから主候補へ上げた以前の説明は、精度優先の判断として採用しない。** WhisperKit・faster-whisper・MacWhisperは主に実行・利用方法として評価する。

選択した数箇所の正誤率や、他モデル同士の多数決は精度の点数にしない。どの候補にも数字・製品名・増減や動作の意味が変わる箇所があり、最終採用には同じ原音に対する検証済み参照での比較が必要になる。個人の発話内容を含む横断比較表はGit対象外の`data/asr/evaluation/overall-accuracy-review.md`に置く。
