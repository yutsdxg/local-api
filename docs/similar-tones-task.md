# 指示
別プロジェクトで開発した[similar-tones](references/similar-tones)をlcoal-apiに移植したいです。以下の要求に従って開発計画を立ててください。ユーザーが開発計画を確認して、問題がなければ実装に入るため、それまではソースコードに手を入れないでください。開発にあたり情報が不足する場合はユーザーに問い合わせしてください。

- local-apiの中の一つのエンドポイントとして機能するようにする
- コーディングスタイルはlocal-apiの他の処理に合わせる
- AnalyzeChordMelodyはdockerコンテナ上で実行するようにしていたが、本プロジェクトのvenv仮想環境内で実行すればよい

## 不足情報への回答
エンドポイント仕様: インデックス作成と検索は別エンドポイントで良いですか？パス名の希望はありますか？

[回答] 以下でお願いします。
- /audio/similar-tones/index
- /audio/similar-tones/search

入力方法: 音声ファイルは「ローカルパス指定」か「アップロード」どちらを想定していますか？

[回答] ローカルパス指定です。ローカルのファイルのみ対象です

出力形式: 検索結果はJSONのみで良いですか？CLIのCSV出力相当が必要ですか？

[回答] はい。JSONは見にくいので、人間が見やすい結果を返して欲しいです。

インデックス保存先: デフォルトのディレクトリ指定（例 data/similar-tones/index）はありますか？

[回答] ないです。ローカルディスクのオーディオファイルのパスを指定します。

モデル実行: CPU前提で良いですか？モデル/キャッシュのダウンロード先を固定したいですか？

[回答] CPU利用の前提で、今後MPUを利用するように改修するかもしれないという前提でお願いします。モデル/キャッシュのダウンロード先は固定でお願いします。
