# Whisper前処理の評価記録（2026-09-23〜24）

## 評価条件

録音直後の原音14本（合計約167.7分）を棚卸しした。形式はALAC、24 kHz、mono、24 bit。うち10本は現行FFmpeg処理を再実行したPCM全体のSHA-256が既存のWhisper入力WAVと一致し、過去のTXTとの対応を特定できた。原音や個人的な発話内容はGitに含めない。

主評価はこの原音から選んだ通常発話90秒、雨音について言及する録音60秒、約24秒の低音量区間を含む録音60秒。各抜粋から `legacy`、`vad`、`vad_normalized`、`deepfilter` の4条件を実行した。天候の説明は過去のTXT由来であり、計測したSNRや正解ラベルではない。

- Whisper: 既存の `ggml-medium.bin`、言語 `ja`、CPU引数 `-ng -nt -np`。
- Silero: v6.2.0、閾値0.5、最短発話100ms、最短無音500ms、前後余白200ms。
- DeepFilterNet: CLI v0.5.6、DFN3 ONNXモデル、抑制上限12dB、追加post-filterなし。
- FFmpeg: 8.1、Apple Silicon。モデル・バイナリ・実装のハッシュはローカルの評価JSONに記録。
- 初期の抜粋比較は各方式で共通の16-bit PCMを使用。評価CLIはその後、24-bit原音の精度を保つ32-bit PCM抜粋へ更新し、全文確認に使用した。

当初指定されていた動画音声はユーザーから別ファイルと訂正されたため、採用判断の主評価から外した。前処理済みジャーナリングWAVの再処理も補助資料のみとした。

## 抜粋での結果

| 条件 | 文章上の観察 |
| --- | --- |
| 通常発話 | 4方式で主要内容は共通。VADでは従来結果より口語表現が多く残る。DFNとVADの差は活用1文字のみで、DFNの追加効果は確認できない。 |
| 雨音に言及する発話 | 全方式で意味の通りにくい語句が残る。VAD側で自然な単語への変化はあるが、数値表現の変動や末尾への擬音・接続語の追加もあり、一律改善は確認できない。 |
| 長い間を含む発話 | 4方式とも短い出力で、長い反復は発生しない。接続部・副詞・助詞は方式ごとに変動する。 |

複数評価を同時実行した時間があるため、所要時間の差は参考値に留める。無音の多さ、文字数、誤生成を含むデコードの長さも時間を左右するため、文字数の減少や高速化を精度向上とは扱わない。

## 全文での確認

雨音に言及する同じ原音全体（実PCM 742.741秒）から、同じ32-bit PCMを各方式へ入力し、Whisperモデル・引数・言語を固定して再実行した。

| 方式 | 出力文字数 | 観察 |
| --- | ---: | --- |
| 過去のlegacy結果 | 1810 | 同一の長いフレーズが11回現れる反復ブロックがある。 |
| 現在のlegacy再実行 | 1813 | 過去と同じフレーズの反復は出ないが、別のフレーズが8回繰り返される長いブロックがある。 |
| VAD | 2007 | 上記2種類の長い反復ブロックは出ない。前後につながる内容が多く残る一方、不自然な語句や数値表現は残る。 |
| DeepFilterNet＋VAD | 1834 | 上記の反復ブロックは出ないが、旧結果とVADの両方にある複数の節が出力されず、固有名詞も不自然な表記になる。 |

この1本では、VADのみが長い反復の抑制と内容保持の比較で有力だった。原発話との全単語一致を確認したものではなく、短い言い直し状の反復も残るため、「全反復解消」「精度が何%改善」とは扱わない。DeepFilterNetは抑制上限を12dBから6dBへ弱めた60秒の追加試験でも、不自然な語句や文の変化が残った。

全文VADとDeepFilterNetは並行実行でそれぞれ約290秒・310秒、legacy再実行は約202秒だった。並行負荷とデコード内容が異なるため、この数値から速度順位を決めない。

## 従来フィルターを残す追加比較（2026-09-24）

「正規化なし」という説明では、従来の帯域カット・動的な音量調整・無音除去を区別できていなかった。初期評価は帯域カットの有無を分離していないため、従来処理をすべて外すことが最善と結論するには不十分だった。VAD・Whisperの設定を固定し、VAD前のFFmpegフィルターだけを次の6条件で比較した。

| 条件 | FFmpegの追加フィルター | 通常90秒の文字数 | 雨60秒の文字数 | 長い間60秒の文字数 |
| --- | --- | ---: | ---: | ---: |
| VADのみ | なし | 245 | 139 | 25 |
| 音量調整＋VAD | `dynaudnorm=f=200:g=7` | 238 | 116 | 30 |
| 低域カット＋VAD | `highpass=f=120` | 248 | 134 | 26 |
| 高域カット＋VAD | `lowpass=f=8000` | 245 | 140 | 25 |
| 両帯域カット＋VAD | `highpass=f=120,lowpass=f=8000` | 245 | 144 | 28 |
| 両帯域カット・音量調整＋VAD | `highpass=f=120,lowpass=f=8000,dynaudnorm=f=200:g=7` | 238 | 32 | 26 |

最後の条件は、従来処理のうち `silenceremove` だけをVADへ置き換えたもの。全条件で16 kHz / mono / PCM s16leへの変換は維持した。同じ16-bit抜粋を再利用し、既存の2条件は入力・モデル・実行ファイルのハッシュと準備後PCM全体の一致を確認して結果を再利用した。残り4条件×3抜粋は新規実行した。文字数は出力変化の所在を示す診断情報であり、精度の順位ではない。

- 通常発話では、高域カットだけ・両帯域カットの結果はVADのみと全文一致。低域カットだけでは短い口語表現が増えたが、改善か誤挿入かは判定できない。両帯域カット・音量調整は音量調整だけと全文一致した。
- 雨音に言及する抜粋では、帯域カットを戻しても不自然な語句が残り、新たに文脈とつながりにくい語句へ変化する例があった。両帯域カット・音量調整では、他条件にある複数の文が出力されなかった。
- 長い間を含む抜粋では、全条件で長い反復は出ず、接続語や助詞などの小さな差が中心だった。

雨の抜粋でSileroの検出区間も確認した。検出区間の合計はVADのみで27.32秒、両帯域カット・音量調整で28.78秒（連結時の重複余白を除く）で、後半にも検出区間があった。したがって文字数の139→32への減少を「VADが後半の音声をすべて削ったため」とは説明できない。音量・周波数成分の変化、区間の境界・連結、Whisperのデコードを区別して考える必要がある。

同じ録音の全文742.741秒でも、既存の32-bit PCMを使い、帯域カットを残す2条件を追加実行した。

| 条件 | 文字数 | 観察 |
| --- | ---: | --- |
| VADのみ（既存結果を再利用） | 2007 | 従来の長い反復ブロックはない。不自然な語句は残る。 |
| 両帯域カット＋VAD | 2030 | 従来の長い反復ブロックはない。語句の改善・悪化、脱落候補が混在する。 |
| 両帯域カット・音量調整＋VAD | 1498 | 従来の長い反復ブロックはない。一部の語句は自然になるが、他条件にある複数の説明が出力されず、文章が途切れる箇所がある。 |

帯域カットを残す条件でも長い反復は出なかったため、反復の改善だけを帯域カットの撤去理由にはできない。一方、今回の比較から従来フィルターを全部残す構成が有利とも判断できない。文字数減少は脱落箇所を調べるきっかけとして使用し、精度悪化率としては扱わない。

## 機能検証

- Python unittest 37件成功。既存API契約、legacy互換、選択モデル不足、処理失敗、中間ファイル削除、反射padding、抑制値の境界を検証した。
- 実バイナリで2秒無音、10秒の約−45dBFS白色ノイズ、100msトーンを `vad` / `deepfilter` へ渡した6ケースすべてで、空textを正常返却した。16kHz変換後の長さと原音ハッシュも保持した。トーンは短い人間の発話を代替する精度試験ではない。
- DFN3の遅延補正では、無音paddingによる語尾欠落を合成信号で確認し、40ms反射paddingで改善した。抑制上限0.01dB未満はCLIの素通しと遅延補正が整合しないため拒否する。
- 原音の末尾にあるゼロsample ALAC packetによりFFmpeg警告が出る。全14本で最終packetだけに同一の状態があり、コンテナ宣言との差は約0.171秒。途中の時刻不連続は確認されず、評価は実デコード後のPCMサンプル数を基準にした。

## 判断の制限

原音を聴取して作成した正解文はない。出力テキストの自然さ、文字数、差分だけでは、発話の復活と誤挿入を確定できないためCERや改善率は算出しない。VADが波形を保持していても、区間連結とWhisperのデコードによって転記が変わる場合がある。

共通PCM32は原ALACのPCM32デコードと完全一致した。ただし、ALAC直接入力と中間WAV入力ではFFmpegのHP/LP内部形式が異なり、legacy出力の全11,366,309 samples中953 samplesに±1 LSBの丸め差があった。時刻・サンプル数の差はない。内部形式をALACと同じs32pへ指定すると歴史的WAVのハッシュを完全再現できた。今回の3方式は同じPCM32から比較しているが、過去TXTとの差をすべて前処理改善に帰属させない。

`vad`・音量調整なしは、確認した録音に対する試用候補とする。「従来のフィルターは個別にすべて不要」「無加工が常に最善」と決定したものではない。特に屋外録音の低域カットは、風・振動の成分によって有用な可能性があり、今回の少数の録音だけでは一般化できない。追加比較は現行と同じ120 Hz / 8 kHz / `f=200:g=7`をVAD前に適用した条件に限り、別の強さやVAD後の処理順は評価していない。

互換性と最終的な運用判断のため、コードの既定は `legacy` を維持する。DeepFilterNetは任意の実験設定とし、全面採用しない。音量調整の効果も素材に依存するため常時有効にはしない。

再現手順は [前処理と比較評価](whisper-preprocessing.md) を参照。
